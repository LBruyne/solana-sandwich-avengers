# sandwich-intent

Turns the sandwich shapes `sandwich-detector` writes into a labelled attacker
dataset.

Inputs are the tables the detector fills (`sandwiches`, `sandwich_txs`,
`slot_txs`, `slot_leaders`, `jito_bundles`). Outputs are per-attacker feature
tables and the sandwiches attributed to each attacker, all under `data/`.

```
ClickHouse (detector tables)
        │
0_*   external data: Jito bundle verdicts, token prices, validator + site snapshots
        │
        ▼
1_signer_data_preparation_and_summary.py     per-sandwich metrics → per-entity features
        │
        ├──────────────▶ 2_parameter_selection_and_sensitivity_analysis.py   (diagnostic)
        ▼
3_attacker_filter.py                         Track 1 / 2 / 2b → the attacker set
        │
        ▼
4_validator_association.py                   attacker ↔ validator enrichment (Signal Bots)
```

Steps 1, 3 and 4 are the pipeline. Step 0 is data acquisition, run once per
measurement window. Step 2 is a diagnostic and feeds nothing downstream.

## Setup

```bash
cd sandwich-intent
pip install -r requirements.txt
cp .env.example .env          # then fill in the credentials
```

`utils/db.py` reads that one `.env` for every step: `CLICKHOUSE_*` for the
database (`CLICKHOUSE_DATABASE` sets the default; every script also takes
`--database`), plus `MORALIS_API_KEY`, which `0_crawl_token_price.py` needs to
price the tokens — a free Moralis project key is enough. An unset credential
stops the run.

Two helpers reach the chain directly (`utils/check_owner_accounts.py` and
`tests/build_audit_bundles.py`). They shell out to a script with the contract
`rpc.sh <method> <params-json>`, so the endpoint's API key stays out of the
Python process:

```bash
cp rpc.sh.example rpc.sh && chmod +x rpc.sh    # then set the endpoint inside
```

Point `SOLANA_RPC_CMD` elsewhere if you keep it somewhere else. Use an
**archival** endpoint for a historical window. Nothing else needs RPC access.

**Which database.** `solwich` is the default and is what a fresh run of
`sandwich-detector` fills. Pass `--database <name>` (and `INTENT_DB=<name>` for
the tests) to point the pipeline elsewhere.

`data/` is regenerated by the pipeline and is gitignored, except for three
committed inputs:

| Committed under `data/` | Contents |
|---|---|
| `token_prices/prices.csv` | The USD price snapshot every USD figure is computed against. |
| `jito_bundle_ids/*.csv` | The Jito bundle verdicts for epochs 946–990. |
| `expert_audit/results/cases_summary.csv` | The blinded panel's adjudicated verdict per attacker. |

## Step 0 — data acquisition

| Script | Output | Required by |
|---|---|---|
| `0_crawl_jito_bundle_ids.py --start-epoch 946 --end-epoch 990` | `data/jito_bundle_ids/` | **Steps 1 and 3** (Track 1). Resolves each sandwich leg's bundle ID from the Jito API and records which sandwiches sit entirely inside one bundle. Missing input is a hard error, not an empty result. |
| `0_crawl_token_price.py [--top-n 100]` | `data/token_prices/prices.csv` | **Step 1** and every USD figure. One table, loaded once, via `utils.intent.load_token_prices`. |
| `0_crawl_stakewiz.py` | `data/stakewiz/validators.{csv,parquet}` | Nothing in the pipeline. Validator identity/stake/ASN metadata for the paper's tables. |
| `0_crawl_sandwiched_me.py --epoch 946` | `data/sandwiches_site_epoch_946.csv` | Nothing in the pipeline. A public feed used only as an external recall benchmark for the detector. |
| `0_report_data_overview.py --start-epoch 946 --end-epoch 990` | stdout | Nothing. Coverage and structural summary of the window; `--sections` selects which of the six to print. |

A token absent from the price table is **unknown**, not zero: it drops out of
both numerator and denominator wherever USD is aggregated. `usd_total_profit`
is `NaN`, not `0.0`, when nothing an entity traded had a price.

`0_crawl_jito_bundle_ids.py` fails rather than returning an empty set when its
output directory holds nothing for the requested range.

## Step 1 — per-sandwich metrics and per-entity features

```bash
python 1_signer_data_preparation_and_summary.py \
    --start-epoch 946 --end-epoch 990 \
    --category {standard|multi_split|diff_signer_owner|diff_signer_transfer} \
    --cross-leader {include|exclude|only}
```

**Categories** are structural, and do not partition the corpus:

| Category | Shape |
|---|---|
| `standard` | same signer front and back, not multi-split |
| `multi_split` | same signer, front **or** back split across several transactions |
| `diff_signer_owner` | different signers, shared token-B owner, not multi-split |
| `diff_signer_transfer` | different signers, no shared owner — linked only by an inline transfer |

`diff_signer_transfer` names its attacker by the front-run's fee payer, since
its two legs share neither a signer nor an owner.

**Ordering gaps**, in transaction-count units along the slot axis, with
distances spanning slots via a prefix sum over `slot_txs.txCount`:
`front_gap` = first front-run tx → first victim tx; `back_gap` = first back-run
tx → last victim tx.

**Slippage consumption (SC)** is recomputed here from the raw amounts on each
victim leg — `slippageLimitType`, `slippageLimitAmount`, `slippageActualAmount` —
rather than read from the detector's `slippageUtilization`, so one rule applies
to every row:

- per victim: `output` limit → `limit / actual`; `input` limit → `actual / limit`;
- the band is `[0, 1]` and only the ceiling rejects — `SC > 1` means the decoded
  limit did not bind, so consumption is unknown;
- a zero or nominal limit (an aggregator's 1-raw-unit `min_out`, a literal 0)
  yields `SC ≈ 0`, which is a measurement, not a failure;
- per sandwich: `max` over the victims **at or above a 0.01 protection floor**.
  Sub-floor victims are dropped from the max rather than competing in it at 0.
  **Any** anomalous victim voids the whole sandwich;
- per entity: `mean_SC` over that entity's **scored** sandwiches.

That leaves three outcomes per sandwich, not two:

| Outcome | Column | Meaning |
|---|---|---|
| scored | `sc` | at least one protected victim; `sc` is their max |
| anomalous | `sc_anomaly` | consumption **cannot be measured** |
| unprotected | `sc_unprotected`, reason `no_protection` | measured, but no victim set a binding tolerance |

An unprotected sandwich is **not** scored 0. Both non-scored outcomes are `NaN`
plus an explicit boolean and a reason — never a number — and leave both the
numerator and the denominator, so "cannot be judged" never becomes "judged low".
`sc_coverage`, `sc_anomaly_rate` and `unprotected_rate` report the three shares;
read the last with the caveat that `no_protection` conflates "the victim set no
bound" with "the bound is outside the detector's decode scope".

**Entity resolution.** For `diff_signer_owner`, signers are merged into entities
before aggregation; `--entity-merge {legacy|feepayer|owner|owner+guard}`
(default `owner`) selects the anchor relation, `n_signers` records how many
on-chain keys the entity controls, and the run reports the cluster-size
distribution and flags concentrated entities. Owner anchors that are SPL token
accounts rather than wallets are filtered using the cache built by
`utils/check_owner_accounts.py`; without that cache the run says so and proceeds
unfiltered.

**Profit floor.** Entities below `--profit-floor-usd` (default **$100** net over
the whole range) are dropped after aggregation. Entities whose sandwiches are
*all* verified Jito bundle sandwiches are exempt when positive. Pass
`--profit-floor-usd 0` for the unfiltered population.

**Cross-leader.** `--cross-leader` selects which geometries enter the run:
`include` (the default, all of them), `exclude` (single-leader only) or `only`
(the cross-leader slice). Steps 2 and 4 compare the two populations, so
**run step 1 twice, with `include` and with `exclude`**, before either.

Outputs — `data/1_signer_data_preparation_and_summary/<category>/<database>/`,
tagged `<start>_<end>` for `exclude` and `<start>_<end>_cl-<variant>` otherwise:

- `per_sandwich_metrics_<tag>.parquet` — one row per sandwich;
- `signer_features_<tag>.{parquet,csv}` — one row per entity; consumed by steps 2 and 3;
- `signer_summary_all_<tag>.csv` — human-readable;
- `diagnostics_<tag>.json` — counts dropped at each stage, including the floor;
- `charts/` — WR / SC / gap / count / USD distributions.

## Step 2 — threshold sensitivity (diagnostic)

```bash
python 2_parameter_selection_and_sensitivity_analysis.py \
    --start-epoch 946 --end-epoch 990 --category standard
```

Measures each step-3 gate **on the population that gate actually sees**, in the
order the gates apply:

| Stage | Gate | Measured over |
|---|---|---|
| 1 | `sandwich_count ≥ 100` | every entity |
| 2 | `sol_win_rate ≥ 0.85` | survivors of stage 1 |
| 3a | `mean_SC ≥ 0.90` | survivors of stage 2 |
| 3b | `front_gap_p50 ≤ 75` | survivors of stage 2 |
| 4 | — | the selected set, after all gates |

Stages 3a and 3b are **parallel**, both on stage 2's output: chaining them would
make each one's curve depend on the other's operating point, and the two
measure independent signals. Each stage emits a bucket table (attackers,
sandwiches, net profit per band) and a sweep table (running totals at or below
each threshold, plus the `≥` complement), for both cross-leader variants.

Outputs: `data/2_parameter_selection_and_sensitivity_analysis/<category>/<database>/<start>_<end>/{include_XL,exclude_XL}/{data,charts}/`.

## Step 3 — attacker filter

```bash
python 3_attacker_filter.py --start-epoch 946 --end-epoch 990 \
    --category <cat> --cross-leader {include|exclude}
```

Two tracks, applied uniformly across categories. Every threshold is the
script's default and is overridable on the command line.

**Track 1 — Jito Bot.** At least one *verified bundle sandwich*: one `bundleId`
holding the front-run, a victim and the back-run, with `signerSame` and
`profitA > 0`. No count threshold and no USD floor.
`tests/test_bundle_definition.py` pins this one definition across scripts 0, 1
and 3.

**Track 2 — Signal Bot.** All of:

| Gate | Default | Signal |
|---|---|---|
| `sandwich_count ≥ n_min` | 100 | sustained activity |
| `sol_win_rate ≥ wr_min` | 0.85 | economic motivation |
| `usd_net_total ≥ signal_usd_min` | $10 | non-trivial take |
| `mean_SC ≥ slip_min` | 0.90 | victim observation |
| `front_gap_p50 ≤ fg_median_max` | 75 | ordering control |

The win-rate gate is on `sol_win_rate` — tokenA is SOL, so profit and fee share
a unit and no price table enters the test. `win_rate` is a rate over the
priceable subset only and is reported, not gated on.

**Track 2b — Oneshot Bot** (`multi_split` only, **off unless `--oneshot`**):
`sandwich_count ≤ 5` **and** `sol_win_rate ≥ 0.85` **and** `usd_net_total ≥ $100`.
Captures single high-value attackers, e.g. pump.fun launch races, that fall
below Track 2's count gate.

**All USD is net** — the entity's profit minus the fees it paid on its own
front-run and back-run legs. The detector's `profitA` is a swap-amount
difference with no cost side.

Tiers emitted: `jito_and_signal`, `jito_only`, `signal`, `signal_and_oneshot`,
`oneshot`, `unclassified`. Each attacker is also annotated with the blinded
expert panel's `expert_verdict` (`yes` / `no` / `ambiguous` / `not_audited` /
`no_audit_for_tag`) as an **annotation, not a filter**: entities the panel
overturned stay in the table, and dropping them is a downstream decision.

Outputs — `data/3_attacker_filter/<category>/<database>/<include|exclude>/`:

- `bot_attackers_<tag>.{parquet,csv}` — one row per attacker, full feature set, `tier`, `expert_verdict`;
- `bot_sandwiches_<tag>.parquet` — every sandwich attributed to an attacker;
- `bot_sandwiches_geom_<tag>.parquet`, `attacker_geometry_<tag>.csv` — ordering geometry (skip with `--no-geometry`);
- `pool_signers_<tag>.csv` — the Track 2 pre-filter pool;
- `all_signer_tiers_<tag>.csv` — a tier for every signer in the category;
- `charts/` — pre-filter WR distribution and the SC × front-gap views.

Every category run also rewrites the union across categories to
`data/3_attacker_filter/_merged/<database>/<variant>/all_attackers_<tag>.{parquet,csv}`
— **this is the attacker dataset**.

## Step 4 — validator association

```bash
python 4_validator_association.py --start-epoch 946 --end-epoch 990
```

Measures how often each attacker's sandwiches fall near each validator's leader
rotations, against that validator's own share of the chain.

Scope:

- **Signal Bots only.** A Jito Bot's ordering comes from a bundle it paid for,
  so its leader is set by Jito's routing.
- **Step-3 output only**, minus entities carrying `expert_verdict == "no"`. No
  second count or profit threshold is applied here.
- **Single-leader sandwiches only.** A sandwich is placed at its front-run's
  slot, so a cross-leader sandwich has its back-run in a later rotation by
  construction. `--include-cross-leader` keeps them.
- **Both cross-leader populations**, run automatically and written to separate
  directories.

The window is **±2 leader rotations** — the rotation holding the sandwich, two
before and two after, 5 positions. Solana rotations are 4 slots, so this spans
roughly 20 slots. Enrichment, per (attacker `a`, validator `v`):

```
    η_av  =  observed_rate / expected_rate
          =  (N_av / |S_a|) / Σ_offset P(v leads at that offset)
```

`N_av` counts how often `v` appears anywhere in `a`'s windows and `|S_a|` is
`a`'s sandwich count, so the five offsets are summed, not averaged. The
denominator is measured from `slot_leaders` over the same slot range, so it
already carries that window's stake distribution and skipped-slot pattern.
η = 1 is chance; η = 10 means ten times what `v`'s share of the chain predicts.

Defaults: `--min-enrichment 10`, `--min-near-cnt 5`, `--cohort-min-shared 3`,
`--trusted-top-n 15`.

Outputs — `data/4_validator_association/<database>/{include_XL,exclude_XL}/`:

- `data/flagged_pairs_<tag>.csv` — every `(attacker, validator)` pair at or above `--min-enrichment`;
- `data/untrusted_pairs_<tag>.csv` — the same, excluding the top-N validators by slot share;
- `data/signer_top_validator_<tag>.csv` — each attacker's strongest validator and η;
- `data/cohort_members_<tag>.csv` — attackers grouped into cohorts by shared flagged validators;
- `charts/` — enrichment overview and cohort fingerprint.

## End to end

```bash
DB=solwich; S=946; E=990

# 0 — external data (once per window)
python 0_crawl_token_price.py     --database $DB --top-n 100
python 0_crawl_jito_bundle_ids.py --database $DB --start-epoch $S --end-epoch $E
python 0_crawl_stakewiz.py                                            # paper tables only
python 0_report_data_overview.py  --database $DB --start-epoch $S --end-epoch $E

# prerequisite for the diff_signer_owner entity merge (needs rpc.sh)
python utils/check_owner_accounts.py --database $DB --start-epoch $S --end-epoch $E

# 1 — features, BOTH cross-leader variants (steps 2 and 4 compare them)
for XL in include exclude; do
  for CAT in standard multi_split diff_signer_owner diff_signer_transfer; do
    python 1_signer_data_preparation_and_summary.py \
        --database $DB --start-epoch $S --end-epoch $E --category $CAT --cross-leader $XL
  done
done

# 2 — sensitivity (diagnostic; reads both variants itself)
for CAT in standard multi_split diff_signer_owner; do
  python 2_parameter_selection_and_sensitivity_analysis.py \
      --database $DB --start-epoch $S --end-epoch $E --category $CAT
done

# 3 — classification; every category run rewrites _merged/
for XL in include exclude; do
  for CAT in standard multi_split diff_signer_owner diff_signer_transfer; do
    python 3_attacker_filter.py \
        --database $DB --start-epoch $S --end-epoch $E --category $CAT --cross-leader $XL
  done
done

# 4 — validator association (runs both variants in one invocation)
python 4_validator_association.py --database $DB --start-epoch $S --end-epoch $E
```

Every script accepts `--help`, and none of them requires a reachable ClickHouse
to print it.

## Tests

```bash
python -m pytest tests/ -q                    # against $CLICKHOUSE_DATABASE
INTENT_DB=<database> python -m pytest tests/ -q
```

- `tests/test_bundle_definition.py` — pins the one Jito bundle-sandwich
  definition (one `bundleId` over front + victim + back, `signerSame`,
  `profitA > 0`) across scripts 0, 1 and 3.
- `tests/test_slippage_rule.py` — pins the SC rule: the `[0, 1]` band, the
  ceiling rejection, the inclusive protection floor, `max`-with-anomaly
  propagation, and that the three per-sandwich states partition the population
  with `mean_SC` denominated on the scored ones only.
- `tests/build_audit_bundles.py` — rebuilds the blinded case bundles the expert
  panel reviewed. A generator, not a test; pytest does not collect it.

```
3_*.py                       attacker classification

utils/db.py                  ClickHouse client, env-driven
utils/intent.py              definitions shared across scripts: tags, price table,
                             bundle verdicts, USD conventions

```
